# API Automation Framework — Theory

We have designed our API automation framework using **Java, Rest Assured, and TestNG**. The framework follows a **layered architecture** to keep responsibilities clear and tests maintainable. For detailed implementation guidance, refer to **1.1-RestAssured_Framework_Guide.md**.

## Core Components

- **Configuration Manager**
  - Reads environment-specific configuration such as API base URLs, credentials, and timeouts.
  - Loads from property files (dev.config.properties, qa.config.properties, stage.config.properties).

- **RestClient (common HTTP layer)**
  - Encapsulates Rest Assured request execution for GET, POST, PUT, PATCH, and DELETE.
  - Builds RequestSpecification with headers, authentication, content-type, and query parameters.
  - Manages authorization header injection and logging.

- **Prerequisite / Authentication Layer**
  - Invokes authentication APIs when required; retrieves and caches access tokens.
  - Exposes tokens to subsequent requests via RestClient.
  - Handles token refresh and expiry concerns.

- **BaseTest (TestNG Fixtures)**
  - Manages common setup and teardown via `@BeforeTest`, `@BeforeMethod`, `@AfterMethod`, `@AfterTest`.
  - Initializes RestClient with properties and baseURI.
  - Configures Allure reporting filters.
  - Exposes service endpoint constants (e.g., GOREST_ENDPOINT = "/public/v2/users").

- **Test Layer (TestNG @Test Methods)**
  - Contains TestNG test methods with `@Test` annotation.
  - Uses `@DataProvider` for data-driven testing (multiple test scenarios).
  - Uses `@Parameters` to receive values from TestNG XML configuration.
  - Follows Arrange-Act-Assert (AAA) pattern for clarity.
  - Asserts response status, body, and headers.

- **Payloads and Mapping**
  - Request and response payloads are modeled as POJOs using **Lombok** to reduce boilerplate.
  - **Jackson Databind** is used for JSON serialization/deserialization.

- **Data-driven Testing**
  - **Excel Utility** provides multiple combinations of test data to drive scenarios.
  - **TestNG DataProvider** supplies test data programmatically to `@Test` methods.
  - Tests run multiple times with different inputs from external sources.

- **Utilities, Constants and Enums**
  - Reusable helpers (ExcelUtility, JsonPathValidator, StringUtils) live in a common utilities package to avoid duplication.
  - Domain enums (APIHttpStatus, APIConstants) centralize shared resources.

- **Reporting**
  - **Allure** is used for comprehensive test reporting.
  - Request/response bodies and headers are logged automatically via `RestAssured.filters(new AllureRestAssured())`.
  - Execution artifacts are produced under `allure-results/`, used to generate interactive HTML reports.
  - Custom steps can be marked with `@Step`, `@Feature`, `@Story`, `@Description` annotations.

## Design Principles

- **Reusability** — Common utilities, constants, and RestClient methods shared across all tests
- **Readability** — Clear separation of concerns; test methods read like plain English
- **Maintainability** — Centralized configuration; changes propagate to all tests
- **Scalability** — Layered architecture supports thousands of tests
- **Reliability** — Token refresh logic, error handling, and comprehensive logging

This concise overview is useful for explaining the architecture and design choices during design discussions. For detailed patterns, code examples, and best practices, refer to **1.1-RestAssured_Framework_Guide.md**.
