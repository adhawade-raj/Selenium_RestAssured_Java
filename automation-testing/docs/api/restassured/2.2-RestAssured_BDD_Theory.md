# BDD API Automation Framework — Framework Explanation

We have built a **BDD-based API automation framework** using **Java, Rest Assured, Cucumber and JUnit**. The framework follows a layered architecture where the Feature Files contain business-readable scenarios in **Given-When-Then** format, and the Step Definitions provide the Java implementation for those steps.

We use **Cucumber `@Before` and `@After` Hooks** for scenario-level setup and teardown. Instead of using a TestNG `BaseTest`, the required framework components are initialized through our Cucumber setup and dependency injection is handled using **Google Guice with `@Inject`**.

The actual API communication is handled by a reusable **RestClient** built using Rest Assured. The RestClient is responsible for creating the `RequestSpecification`, handling the base URI, headers, authentication, query parameters, path parameters, request body and API execution for methods such as GET, POST, PUT, PATCH and DELETE.

We reused the common components from our existing **1.1 API automation framework**, such as the RestClient, ConfigurationManager, authentication logic, POJOs and common utilities. On top of these reusable components, we introduced the BDD layer consisting of Feature Files, Step Definitions, Cucumber Hooks and the Cucumber JUnit runner.

**ConfigurationManager** handles our environment- and channel-specific configuration. Based on the selected environment and channel, it resolves the required properties such as base URLs, credentials, paths and test-data locations. This allows us to execute the same automation code across different environments without hardcoding environment-specific values.

For request and response payloads, we use **Java POJOs with Lombok**, and **Jackson Databind** is used for JSON serialization and deserialization. For data-driven testing, we primarily use **Cucumber Scenario Outlines with Examples**, and where larger external datasets are required, we use our Excel utility. We do not use TestNG `@DataProvider` because this is a Cucumber JUnit BDD framework.

For reporting, we use **Allure**. The Rest Assured Allure filter captures request and response details, which makes API failures easier to analyze from the generated report.

Overall, the framework separates the **BDD layer, test execution, API communication, configuration, authentication, data handling, validation and reporting**. This gives us a reusable and maintainable framework while avoiding duplication by reusing the common components from the existing 1.1 framework.

## One-Line Architecture

```text
Feature File
     ↓
Step Definitions
     ↓
Cucumber Hooks + Google Guice DI
     ↓
RestClient
     ↓
Rest Assured
     ↓
API
     ↓
Response Validation
     ↓
Allure Report
```
