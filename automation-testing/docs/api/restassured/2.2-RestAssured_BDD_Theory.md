# BDD API Automation Framework — Framework Explanation

We have built a **BDD-based API automation framework** using **Java, Rest Assured, Cucumber and JUnit**. The framework follows a layered architecture where the Feature Files contain business-readable scenarios in **Given-When-Then** format, and the Step Definitions provide the Java implementation for those steps.

We use **Cucumber `@Before` and `@After` Hooks** for scenario-level setup and teardown. The required framework components are initialized through our Cucumber setup, and dependency injection is handled using **Google Guice with `@Inject`**.

The actual API communication is handled by a reusable **RestClient** built using Rest Assured. The RestClient is responsible for creating the `RequestSpecification`, handling the base URI, headers, authentication, query parameters, path parameters, request body and API execution for methods such as **GET, POST, PUT, PATCH and DELETE**.

**ConfigurationManager** handles our environment- and channel-specific configuration. Based on the selected environment and channel, it resolves the required properties such as **base URLs, credentials, paths and test-data locations**. This allows the same automation code to execute across different environments without hardcoding environment-specific values.

For request and response payloads, we use **Java POJOs with Lombok**, while **Jackson Databind** is used for JSON serialization and deserialization.

For data-driven testing, we use Cucumber Scenario Outlines with Examples when the test data is small and needs to be visible in the feature file. For large or externally maintained datasets, we use our Excel utility to read test data at runtime. The feature file can pass a test-case ID or Excel file reference, and the Step Definition retrieves the corresponding data through the Excel utility before constructing the request and invoking the RestClient.

For reporting, we use **Allure**. The Rest Assured Allure filter captures request and response details, making API failures easier to analyze from the generated report.

Overall, the framework separates the **BDD layer, test execution, API communication, configuration, authentication, data handling, validation and reporting**. This provides a reusable, maintainable and scalable structure for API automation.

## One-Line Architecture

```text
Feature File
     ↓
Step Definitions
     ↓
Cucumber Hooks + Google Guice DI
     ↓
ConfigurationManager
     ↓
RestClient
     ↓
Rest Assured
     ↓
API
     ↓
Response Validation
     ↓
Allure Report
```
