- Purpose: reusable REST API automation framework using RestAssured and TestNG, focused on readability, reusability and CI-friendly reporting.
- Tech stack: Java (module-specific: 1.8 / 17 / 21), RestAssured 5.x, TestNG, Jackson, json-schema-validator, Allure/Extent for reporting; Maven used for build (check module pom.xml).
- Hybrid approach: supports API-first testing and can integrate UI modules; supports data-driven, BDD (where present) and utility-driven patterns—mix-and-match per module.
- Configuration: centralized properties/Owner-based config provides baseURI, credentials and environment flags; BaseTest or listeners apply these at startup.
- Request/Response reuse: RequestSpecBuilder and ResponseSpecBuilder centralize headers, auth, timeouts and common assertions.
- Data-driven: external JSON/CSV or TestNG @DataProvider feed tests; DataLoader utilities map files to POJOs.
- Mapping & validation: responses map to POJOs via Jackson; json-schema-validator enforces contract compliance.
- Utilities: logging, token managers, retry/awaitility helpers, random data generators and common assertion helpers are shared across clients and tests.
- Flow (one-line): config -> BaseTest/listener -> Test -> RestClient/BaseClient -> RequestSpec -> RestAssured call -> Response -> POJO/assertion -> report.
- CI & execution: Maven + TestNG suites run in CI (Jenkins/Docker); reports/artifacts archived from allure-results/extentReport.
- Best practices: keep tests deterministic and focused, centralize shared behavior, avoid hardcoding endpoints in tests, prefer small stable data sets and reuse Request/Response specs.
